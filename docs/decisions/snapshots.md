# Decision (draft): how this repository publishes a series, named by its digest

**Status: DRAFT, proposed in the pull request for #25 for Eleonora to review. Not in force until she merges it.**

Step 4 of #25 asked for this convention. It is the one every later input (L2, L3, L5) and the H7 estimate follow, and
the one the model repo reads by digest ("it reads this repo's published snapshot by digest",
`docs/research/plan.md`).

## The proposal

- **A series is published in two files under `snapshots/<series>/`:**
  - `manifest.json`, at a stable path: it says which bytes are the series now;
  - `<sha256>.csv`, the bytes themselves, named by their own SHA-256.
- **A published file is never edited or deleted.** A changed series (a new FOMC row, say) is a new `<sha256>.csv` and a
  new `manifest.json`; the old file stays, so a reader who pinned the old digest still finds it. The manifest is the
  only file that changes in place, and it is regenerated by `scripts/build_snapshots.py`, never edited by hand.
- **The manifest carries:**
  - `sha256`, `path`, `columns`, `rows`, `first_announced`, `last_announced`, `last_effective`;
  - `source_table` (the tracked table the bytes are a copy of) and `source_pages` (the sha256 of the saved
    federalreserve.gov page behind each row);
  - `parent_commit` and `parent_panel_sha256`: the parent pin the snapshot was built under
    (`repo_liquidity.PARENT_COMMIT`, `PANEL_SHA256`);
  - `repo_commit`: the commit of this repository the snapshot was built from. A manifest cannot name the commit that
    contains it, so this is the commit before it: the build refuses a tree with uncommitted changes outside
    `snapshots/`, and the snapshot is committed in the next commit.
- **A reader names the digest it expects** (`repo_liquidity.snapshots.read(series, sha256=...)`). A mismatch, or a file
  that is not the bytes its name says, raises `ValueError`. The model repo cites a series by that digest.
- **CI rebuilds every snapshot** from the tracked table and saved pages and requires the rebuilt manifest to equal the
  tracked one (`tests/test_snapshots.py`, `scripts/build_snapshots.py --check`).

## Not decided here

- **Whether `repo_commit` should instead be the commit that adds the snapshot**, which needs a second commit to record
  it or a manifest kept outside the tree. Proposed: the preceding commit, as above.
- **Whether a later series that is not a copy of a table** (the H.8 groups, the H7 estimate) keeps the same layout.
  Proposed: yes, with `source_table` replaced by the inputs it is computed from, named by digest.
- **The rate tables stay where they are** (`tests/fixtures/snapshots/fomc_notes/`): the Stage 4 freeze and the record
  checks read them there. The snapshot is a byte-identical copy.
